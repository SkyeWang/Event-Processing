# 数据收集任务书：八大前沿科技领域事件三元组数据集

> 本文档是给数据收集方（AI/人工）的完整工作说明。收集完成后按本规范验收，请先通读再动手。

---

## 0. 任务一句话

围绕 **8 个前沿科技领域**，收集中英文真实文本，并将其标注成 **"头实体-行为动词-尾实体"三元组**，按指定格式交付 CSV 文件。

这些数据将用于训练一个图神经网络（GNN）链接预测模型，并支撑一个"事件三元组抽取 + 事件链构建"演示系统。**数据的真实性、实体词表的丰富度直接决定最终效果。**

---

## 1. 交付物与格式规范（最重要，务必严格遵守）

### 1.1 交付目录结构

```
交付目录/
├── ch/                                   # 中文
│   ├── BCI_百度新闻_with_verbs.csv
│   ├── 量子科技_必应学术_with_verbs.csv
│   ├── ...
├── en/                                   # 英文
│   ├── quantum_youtube_with_verbs.csv
│   ├── ...
└── README.md                             # 各文件行数与来源说明
```

### 1.2 文件命名规则（代码会按文件名识别领域，必须遵守）

```
{领域关键词}_{来源}_with_verbs.csv
```

- 文件名**必须以 `_with_verbs.csv` 结尾**（处理脚本按此模式扫描）
- 领域关键词必须使用下面第 2 节表格中给出的写法（特别是 `BCI` 和 `6G`，代码按文件名硬编码识别这两个领域）

### 1.3 CSV 格式要求

- 编码：**UTF-8 无 BOM**（带 BOM 会导致程序读不了第一列）
- 表头（第一行，列名必须一字不差）：

```csv
entity1,relation,entity2,source_text,source_type
```

| 列名 | 必填 | 含义 | 规则 |
|---|---|---|---|
| `entity1` | ✅ | 头实体（事件的主体） | 名词性短语，见 1.4 |
| `relation` | ✅ | 关系，**必须是行为动词** | 见第 4 节标注规范 |
| `entity2` | ✅ | 尾实体（行为的对象/结果） | 同 entity1 |
| `source_text` | ✅ | 抽出该三元组的**原文句子片段** | ≤120 字符，作为真实性凭证 |
| `source_type` | ✅ | 来源类型 | 中文：`baidu_news` / `bing_academic` / `bilibili_title` / `bilibili_comment`；英文：`bbc` / `cnn` / `twitter` / `youtube_title` / `youtube_comment` |

示例（中文 `量子科技_百度新闻_with_verbs.csv`）：

```csv
entity1,relation,entity2,source_text,source_type
中国,研发,量子技术,"中国近年来持续投入研发量子技术，并取得多项突破。",baidu_news
谷歌,发布,量子芯片,"谷歌发布最新量子芯片，错误率大幅下降。",baidu_news
量子计算机,应用于,密码学,"量子计算机被应用于密码学领域，威胁传统加密体系。",baidu_news
```

### 1.4 实体（entity1/entity2）规则

1. 必须是**名词性短语**：机构、公司、国家、人物、技术、产品、材料、理论、器官/组织等
2. 长度限制：中文 ≤ 15 个字；英文 ≤ 5 个单词
3. **禁止**：代词（"该公司""他们"）、完整句子、纯数字、含 HTML 标签/emoji/@用户名/URL
4. 同一实体写法要**统一**（例如"量子计算机"不要混用"量子电脑/quantum computer 的不同中文译名"），领域内通用叫法优先
5. 鼓励收录**具体命名实体**（华为、超导量子芯片、脑机接口等）——系统会靠实体词表做文本匹配，词表越丰富效果越好；泛指词（"研究人员""相关技术"）占比控制在 10% 以内

### 1.5 红线（违反即整文件拒收）

- ❌ **禁止凭空编造**三元组——每条必须能在 `source_text` 中找到依据，验收时会抽查原文
- ❌ 禁止把任意两个实体随意配对凑数
- ❌ 禁止从小说/散文/广告等非科技内容中抽取
- ❌ 单文件内部完全重复的行（三元组三列全同）超过 5% 即拒收

## 3. 来源与数量要求

### 3.1 来源（按此优先级收集）

**中文：**
| 来源 | 采什么 | 占比建议 |
|---|---|---|
| 百度新闻 | 科技新闻正文 | ~30% |
| 必应学术（Bing Academic） | 论文标题+摘要 | ~20% |
| 哔哩哔哩 | 科技区视频标题/简介 + **评论区热门评论** | ~50%（评论是走量主力，论文同款做法） |

**英文：**
| 来源 | 采什么 | 占比建议 |
|---|---|---|
| BBC / CNN | 科技版新闻 | ~40% |
| Twitter(X) | 科技话题短帖 | ~20% |
| YouTube | 科技频道视频标题/描述 + 热评 | ~40% |

### 3.2 数量配额

**最低验收线**（低于此不收）：

| 档位 | 每领域三元组条数 | 8 领域合计 |
|---|---|---|
| 中文 | ≥ 5,000 条 | ≥ 40,000 条 |
| 英文 | ≥ 2,500 条 | ≥ 20,000 条 |

**推荐目标**（训练效果更好）：中文 ≥ 100,000 条、英文 ≥ 50,000 条。

> 参考：论文最终规模为中文训练集约 454 万条、英文约 154 万条，但那是多来源数月的积累；本任务书按"能跑通系统并有效果"的规模设定，多多益善，但**质量优先于数量**。

每个领域内部要求**多来源混合**（不要只爬一家），同一领域的实体尽量互相交织（如"中国-研发-量子芯片""量子芯片-应用于-气象预报"），让图连通——孤立小团体太多会降低 GNN 效果。

## 4. 标注规范：动词驱动的三元组

### 4.1 核心原则

关系 **必须是行为动词或动词短语**，表达"谁 对谁 做了什么"。这是本数据集与传统知识图谱最大的区别：

- ✅ 合格关系：`研发、发布、收购、投资、导致、应用于、突破、合作、起诉、批准、展示、警告`
- ❌ 不合格关系：`位于、属于、有、是、是...的首都`（属性关系不要）

英文关系用小写动词/动词短语：`develop, launch, acquire, invest in, cause, applied to, achieve, partner with, approve, warn`。

### 4.2 正反例对照

| 原文 | ✅ 正确三元组 | ❌ 常见错误 |
|---|---|---|
| "华为发布首款 7 纳米芯片" | (华为, 发布, 芯片) | (华为, 首款, 7纳米芯片)——关系不是动词 |
| "AI 模型的能耗导致电价上涨" | (能耗, 导致, 电价上涨) | 尾实体太长/含句子——应截取名词性核心"电价上涨"或改"电价" |
| "马斯克访问了特斯拉工厂" | (马斯克, 访问, 特斯拉工厂) | (马斯克, 访问了, ...)——中文关系不带"了/着/过" |
| "该技术有望用于癌症治疗" | (该技术, 应用于, 癌症治疗) | 把"有望用于"整段当关系——取核心动词"应用于" |

### 4.3 补充约定

1. 中文关系长度 2–6 字，去掉"了、着、过、被"等附加成分（"被应用于"→"应用于"）
2. 一句话含多个事件就拆多条三元组，`source_text` 用同一句
3. 跨句因果（"A 上涨，引发 B 恐慌"）鼓励抽取——这是本数据集的特色（事件链依赖它）
4. 英文实体重名大小写统一为首字母大写（专有名词）或小写（普通名词），同一文件内保持一致

---

## 5. 清洗与去重要求

抽取前先对原文做清洗（对应下游代码 `clean_tags` 逻辑）：

1. 去掉所有 HTML 标签（`<p>`、`<a>` 等）、emoji、`@提及`、`#话题#`、URL
2. 多余空白合并为单个空格
3. 同一文件内 `(entity1, relation, entity2)` 三元组完全重复的只保留一条
4. 长度低于 10 字符的文本（如纯"哈哈哈""so cool"）不要作为来源

---

## 6. 合规要求

- 只收集公开可访问内容，遵守目标网站 robots.txt 与访问频率礼仪
- 不收集需要登录的私域内容、个人隐私信息（真实姓名+手机号+住址等组合）
- 评论类内容注意过滤人身攻击、政治敏感内容——只保留科技讨论
- README.md 中列出：每个文件的行数、采集时间范围、采集方式
